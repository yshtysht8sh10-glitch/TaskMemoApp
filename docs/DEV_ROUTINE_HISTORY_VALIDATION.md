# Routine実績表示 DEV検証準備

開発担当からレビュー/リリース担当へ。これは実行前の手順。配信/実Firebase/実機確認はまだ行っていない。PR140（#137）と後続#138の独立レビュー承認を先に取得し、DEV配信と接続の実行担当・範囲を確定する。Productionは対象外。

## 開始条件

使い捨てDEVアカウント、合成Routineだけを使う。DEV表示、project ID、実行build SHAを照合し、Production origin/account/保存領域へ接続していないことを確認する。不明なら停止。実ユーザーのbackupをfixtureに使わず、既存データの初期化/強制同期/キャッシュ削除を手順に含めない。

#117のmissed書込gateは閉じたまま。未達の有効化・実機確認は契約PR139、全producer/backup/旧writer gateの審査・実装後に別途実施する。新3状態の実装が完了した前提で現在のビルドを確認しない。

## 合成確認対象

日/週/月/年Routine、同じ名称で異なるIDの2件、保存済み完了とスキップの混在、0/1/7/8/125件を用意する。必要なfixture投入は承認されたDEV専用手段で行い、歴史的実績を現在周期から作って「保全できた」とは扱わない。各fixtureの元対象日/実操作日時/IDと投入後rawを照合する。

## iPhone PWA PCの確認

1. 日次の保存済み実績を確認し、週次へ変更。周期変更前の日次実績が元日付で残り、完了一覧と対応することを確認する。
2. 週→日、月、年でも同様に確認。フォームで周期を変更中と保存後を区別し、未保存入力で過去履歴を作り替えないことを確認する。
3. 本日生成未処理は-一行。完了後は同日完了一行、取消後は本日生成の-へ戻る。未記録の過去/未来予定は表示されない。
4. 通常7件→すべて表示→50件ずつ追加し全件に到達。先頭/末尾/件数/同名別IDを照合。縮小/閉じる/再オープンでコンパクトへ戻る。
5. iPhoneのソフトキーボード・縦横画面・編集本文のスクロール・シート閉じる・ライト/ダークで確認。5,000件は描画/スクロール実測を別記し、PC純粋関数の時間を代用しない。
6. 閲覧だけの前後で既存診断のCommitted/History/Outbox/receiptに変更がないことを確認。明示完了/取消と閲覧を分けて記録する。
7. 2台で合成実績/周期変更を同期、片方の再起動、backup export/importで元対象日/結果/実操作日時を比較。backup復元は隔離テスト先に限定し、他端末の未同期操作を全置換しない。
8. Undo/Redoは周期変更と現行対応の完了/skipで確認。他日付や他Routineを巻き戻さない。周期変更前のスキップ取消は既知の#117未対応として別記し、成功扱いにしない。

## 記録項目と停止条件

commit/build SHA、端末/OS/browser/PWA、UIDの匿名ラベル、fixture ID/件数、操作順、元日付/実操作時刻、表示件数、同期状態、raw不変性、結果/残課題を記録する。個人本文や認証情報はログに含めない。

不明head、Journal不一致、保存/同期エラー、別scope混入、表示欠落があれば原本保護のまま停止する。データ消失と即断せず、保存原本と表示経路を別に調査する。本人の実機確認前のIssue Close、Production配信・データ変更は行わない。
