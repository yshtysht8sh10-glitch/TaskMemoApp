# #103 来月・来年の期限グループ

2026-10-27。Productionへの配信・データ操作は行わない。

## 承認済み設計

今日／明日／短期間／今週／来週の既存優先順位を維持し、その後は今月→来月→今年→来年→それ以降。
来月は翌暦月、来年は翌暦年、今年は当年の残り、それ以降は翌々年以降。
前方グループが既に分類した日は再分類しない。見出しは実際の残り期間を表示し、重複期間は既存方式で統合する。
12月は来月が翌年1月になるため、今年の空区間は表示上統合し、来月OFFのfallbackでは今年を飛ばす。
OFF時は次の十分な期間を持つONグループへ含める。受け皿がなければ既存の非表示件数へ集計する。

DnD時は次のローカル日時を候補として確認画面に表示し、確定まで保存しない。

- 来月：翌月末日23:59
- 来年：翌年12月31日23:59
- それ以降：翌々年1月1日23:59

別日時指定／キャンセル、保存時の期間再検証、アカウントscope変更時の破棄を維持する。
候補の計算と検証は表示ON/OFFに依存しない。グループ内DnDは既存の手動順位保存。
OFFの来月分が今年へfallbackした後の並べ替えで年末へ期限変更される経路も再現テストで確認した。
DnDへ現在のvisibleGroupIdsを渡し、同じ表示bucket内は期限変更せず順位だけを保存する。
クイック追加も同じcreate定義を使い、期限編集を要求する。duePresetは既存customで保存し新しい列挙値を追加しない。
Routineは引き続き発生回の日時で分類し、futureグループへのDnDで周期・期限・実績を変更しない。

## 設定・移行

設定の正規保存先は従来の端末共通AsyncStorage `@taskmemo/view/list-display/v1`。
Firestoreにアカウント別表示設定はなく、設定の端末間共有は今回追加しない。
クラウドのNode/profile同期はこのキーを変更しない。同じ端末の再読込・ログイン・同期後も設定を維持する。

- 旧保存設定のvisibleGroupIdsをそのまま復元する。存在しない新IDを勝手に追加しないため両方OFF。
- リスト設定が欠けていても、旧Node／他設定／移行journalのAsyncStorageキー、およびV2 IndexedDBの存在を読み取りで確認する。
- 既存痕跡／判定不能時は新グループOFF。DBを新規作成したり、移行原本を変更したりしない。
- 痕跡のない新規利用では両方ON。初期値の決定を保存するので、再起動後に再判定しない。
- 新規端末で既存アカウントへログインした場合はAuth作成日時と自動初期化日時を比較し、自動初期値だけを一度OFFへ補正する。不明な作成日時も保守的にOFF。
- 設定変更・バックアップ復元には自動初期値マーカーを付けない。以後ログインによって明示設定を上書きしない。日時markerは端末内のみ。
- 同期開始は既存readyゲートにより設定復元後となるため、同期が新規作成した保存領域を既存利用と誤認しない。
- 補正と設定保存は既存の保存queueへ直列化し、UI編集revisionで遅い補正が直近の操作を上書きしない。
